# bitcoin-lifeboat — agent notes

## Long-running / timed processes — do not hang the loop

Several stories run a process that does not return promptly: fuzzing
(`cargo fuzz run`), dev servers (`astro dev`, `tauri dev`), `bitcoind` in regtest,
the HWI sidecar subprocess, Playwright E2E, soak tests, and criterion benchmarks.
Run these so they terminate on their own. Do **not** launch one in the background
and then poll for it with a shell wait-loop.

The trap that wedged the loop for ~10h (US-016 fuzz watcher): a wait-loop that
checks `pgrep -f "<pattern>"` where `<pattern>` also appears in the wait-loop's own
command line. `pgrep -f` matches full command lines, so the loop matches *itself*,
its `! pgrep` condition is never satisfied, and it spins forever — which also keeps
the parent agent process alive, stalling Ralph.

Rules:

- Prefer foreground, self-terminating runs. `cargo fuzz run <target> -- -max_total_time=60`
  exits by itself — let it finish, then read the captured output. Don't background it.
- Never wait on a job with a `pgrep -f` whose pattern is in your own command line.
  Wait on the PID directly instead: capture `$!`, then `wait "$pid"` or poll `kill -0 "$pid"`.
  If you must use `pgrep`, exclude self (`pgrep -f "$pat" | grep -vw "$$"`) and anchor on
  the real binary name.
- Bound every wait with a hard `timeout` (e.g. `timeout 300 <cmd>`) so a stall fails fast.
- For doc/desktop sites use `build`, not `dev` (a dev server never returns). For daemons
  and E2E, give the readiness wait an explicit timeout and tear the process down at the end.

`ralph.sh` enforces a per-iteration `timeout` backstop (`RALPH_ITERATION_TIMEOUT`,
default `4h`) that kills a wedged iteration's whole process group, but an individual
story should never depend on it.

## Root docs contract

The shipped Markdown docs live under `docs/` and are checked by
`crates/error-taxonomy/tests/docs.rs`. When adding or renaming a root doc, update the
required-doc list there if the file is part of the MVP docs set. Keep links between
docs relative (`foo.md`, not a stale copied path); the same test scans every shipped
doc except the canonical `docs/PRD-v2.md` and fails on broken relative Markdown links.

`docs/error-codes.md` must stay in lockstep with `ErrorCode::ALL` and each code's
metadata (`code`, `severity`, `title`, `description`, `action`). The docs test enforces
that contract.

## Docs site

`apps/docs-site` is an Astro Starlight static site generated from the canonical root
`docs/*.md` files. Do not edit `apps/docs-site/src/content/docs/` directly; it is
regenerated by `npm run sync` and ignored by git. The sync step also writes
`apps/docs-site/public/CNAME` from `project.config.toml site.domain`, so the site URL and
custom domain stay config-driven.

For docs-site work, run from `apps/docs-site`: `npm run typecheck` and `npm run build`.
The build runs `astro check`, `astro build`, and the internal-link checker. The homepage
hero must keep the verbatim §15.7 "Bitcoin Lifeboat is not a wallet..." paragraph.

## Governance files

Root governance files (`README.md`, `SECURITY.md`, `CODEOWNERS`, GitHub templates)
must stay in sync with `project.config.toml`. `crates/error-taxonomy/tests/governance.rs`
checks the README's four promises and §15.7 not-a-wallet paragraph, the configured
release/docs URLs, SECURITY disclosure/PGP values, and two-maintainer CODEOWNERS entries
for the security-sensitive paths.

## CI workflow

`.github/workflows/ci.yml` runs the PRD §25.6 matrix as an explicit `os` axis plus
Rust/Node axes. The repo root has `rust-toolchain.toml`, so the workflow sets
`RUSTUP_TOOLCHAIN: ${{ matrix.rust }}`; without that env var the `stable` rows would
silently run as 1.78.0 and the matrix would be misleading.

GitHub retired the hosted `macos-13` label after the PRD's matrix was written. Keep
`macos-13` in the matrix `os` axis for traceability, but map it to the supported
`macos-15-intel` runner via `matrix.runner` so actionlint and GitHub Actions can run
the workflow.

Rust coverage is generated once with `cargo llvm-cov --workspace --all-targets --json`
and enforced by `scripts/check-rust-coverage.py`, which aggregates only
`crates/*/src/*.rs` lines per crate and fails below 80%. Write the JSON to
`target/llvm-cov.json` (cargo-llvm-cov does not create parent directories for
`--output-path`). `lifeboat-core` is a pure re-export facade and currently has no
coverable source lines, so the checker reports it as n/a rather than forcing a
meaningless percentage.

US-086 adds a separate `hardware-wallet-emulators` smoke job. It runs
`scripts/hardware-wallet-emulator-smoke.sh` for Trezor, Coldcard, BitBox02, and
Jade. HWI-supported USB devices use deterministic sidecar fixtures; Jade maps to
the QR PSBT encode/decode path because Jade is not a supported HWI USB family in
this release.

## Security and fuzz workflows

`.github/workflows/security.yml` is the PRD §25.7 scanner gate. `cargo audit`
enforces Rust advisories with `--deny warnings`; `npm audit --audit-level=high`
enforces the JS high/critical threshold for both `apps/desktop` and
`apps/docs-site`; `cargo deny --locked check advisories licenses sources bans`
uses `deny.toml`; OSV uploads/reports lockfile findings but is report-only
because the reusable OSV action does not expose a severity threshold and the
current tree has moderate-only dev-dependency findings.

The temporary `RUSTSEC-2026-0009` exception is intentional and duplicated in
`deny.toml`, `osv-scanner.toml`, and the `cargo audit --ignore` CLI argument:
`time >=0.3.47` requires rustc 1.88, while the root MSRV is pinned to 1.78.
The current printpdf fallback uses `OffsetDateTime::UNIX_EPOCH` only for fixed
PDF metadata, not untrusted date parsing. Remove the exception when the root
MSRV moves or the PDF backend no longer pulls `time 0.3.36`.

When adding internal crates to `[workspace.dependencies]`, include an explicit
`version = "0.1.0"` alongside `path = ...`. Current cargo-deny treats unversioned
workspace path dependencies consumed with `workspace = true` as wildcard
dependencies, so the bans check fails unless the path dependency has a version.

Project Fluent (US-097) is root-workspace Rust 1.78 code. Keep
`fluent-bundle =0.16.0` and `unic-langid =0.9.5` pinned unless the root MSRV
moves; `unic-langid 0.9.6` pulls `tinystr 0.8`, which requires Rust 1.82.
The Fluent stack also needs a crate-scoped `tinystr` Unicode-3.0 exception in
`deny.toml`; do not broaden the global license allowlist for it.

`.gitleaks.toml` extends the default rules and allowlists documented test-vector
material under `fixtures/secrets/` and `fuzz/corpus/`, plus local build output
under `target/` and `fuzz/target/`. Do not add real secrets to those paths.

`.github/workflows/fuzz.yml` runs the detached `fuzz/` cargo-fuzz workspace on
nightly. Keep fuzz jobs foreground and bounded with libFuzzer `-max_total_time`
(5 minutes on PR/push, 1 hour on `v*` tags), matching the no-hanging rule above.

## Release workflow

`.github/workflows/release.yml` is the PRD §26 / US-064 release pipeline. It
uses the protected `release-two-maintainer` GitHub Environment on the publish
job; configure that environment in GitHub with two required reviewers before
cutting a real release.

US-099 stable-release gates live in `scripts/verify-release-gates.sh`. Alpha and
beta tags may proceed with placeholders and the docs-site banner. Any public
non-alpha/beta tag must have `docs/security-audit-signoff.json` with completed
audit sign-off, all findings remediated, and no configured placeholder tokens in
tracked files. Run `scripts/verify-release-gates.sh --self-test` after changing
the script, release workflow, `project.config.toml`, or audit docs.

US-098 reproducibility settings are part of the release contract. Root, CLI, and
desktop release jobs set `SOURCE_DATE_EPOCH` from the commit timestamp,
`CARGO_INCREMENTAL=0`, and `RUSTFLAGS=--remap-path-prefix=$GITHUB_WORKSPACE=.`
plus `$HOME=~`. Local Tauri reproductions should go through
`scripts/reproducible-tauri-build.sh`; the two-checkout proof is
`scripts/demo-reproducible-tauri-build.sh`.

Tauri installers are built with `tauri-apps/tauri-action@v1` from
`apps/desktop`. Keep using the local `npm run tauri` script so the action uses
the pinned `@tauri-apps/cli` dependency instead of downloading an implicit CLI.
Do not enable `uploadUpdaterJson` or add any updater plugin/config.

Paid OS signing is intentionally conditional. Apple notarization turns on only
when all Apple secrets named in the workflow are present; Windows OV signing
turns on only when the Azure Trusted Signing secrets are present. If those
secrets are absent, the workflow still builds artifacts and publishes an
`*.os-signing.txt` marker labeling the installer OS-unsigned. minisign +
cosign signing stays mandatory for every release and the publish job fails if
`MINISIGN_PRIVATE_KEY` or `MINISIGN_PUBLIC_KEY` is missing. The minisign CI key
must be generated for non-interactive use (for example, `minisign -G -W`) and
stored only as a GitHub Actions secret; the public key goes in the repository
variable.

## Signet/PSBT drill crates

`crates/signet-lab` and `crates/psbt-drill` are detached workspaces.
`bdk_wallet 3.0.0` declares Rust 1.85.0, so the BDK practice-wallet and PSBT
drill code pins local `rust-toolchain.toml` files instead of raising the root
Rust 1.78 MSRV. Keep BDK in these detached drill crates only; do not add BDK to
`lifeboat-core` or the core audit/reporting crates.

Run checks from the touched detached crate directory:
`cargo fmt --all -- --check`, `cargo clippy --workspace --all-targets -- -D warnings`,
and `cargo test --workspace`. The root `cargo {fmt,clippy,test} --workspace`
gate intentionally excludes these crates.

`crates/psbt-tools` is different: it is a root-workspace Rust 1.78 crate for
PSBT file import/inspection/extract commands that need no wallet state. Keep BDK
out of it. If a PSBT operation needs disposable wallet state, it belongs in the
detached `psbt-drill` crate instead.

## Packaging metadata

Homebrew, Debian apt, and Flatpak channel files live under `packaging/`. Run
`scripts/verify-packaging.sh` after changing them; it validates/stages the
metadata without release secrets, Ruby, Flatpak Builder, or GUI system libraries.
The release workflow runs the same packaging gate before publishing artifacts.
